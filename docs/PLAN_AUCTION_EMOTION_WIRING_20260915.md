## 1. ⭐ 时间窗台账（本次要立的方法论）

把动作按「是否依赖现场窗口」分成三类，避免再出现「排期项错过窗口」：

| 类别 | 判据 | 本方案中的动作 | 排期规则 |
|---|---|---|---|
| **A. 窗口独占** | 数据只在某时点存在（竞价 09:15–09:25、外盘 08:3x、盘前情绪 09:00–09:15） | 竞价全量快照、盘前情绪快照 | **必须提前一个交易日就位**，错过 = 丢一天 |
| **B. 窗口无关** | 源码/配置/离线分析 | join 脚本、判别检验、文档 | 随时可做 |
| **C. 决策实时** | 影响买卖判定 | `--pattern-gate`、温度闸 | 取样日**不碰**（红线） |

**本方案 = 只做 A + B，完全不碰 C。**

## 2. P0（今晚执行，唯一改动的文件：`scripts/auction_monitor.py`）

### 2.1 为什么改动只能落在这里（风险论证）
| 事实 | 依据 |
|---|---|

| 时段**独占** | 09:15–09:29 只有它在跑，不会与 scan（09:30 起）抢资源 |

⇒ **改它的爆炸半径 ≈ 0**。这是本次唯一能「今晚改、明早用」而不用冒取样日风险的位置。

### 2.2 改什么（3 项，全部「只加字段、不改判定」）

**① `freeze.pool_snapshot` —— 从 24 只扩到「昨日战法池全量」**
```
输入：outputs/patterns/<day>_pattern_pool.json  (asof = T−1，池 1546 只)
      ∪ outputs/plans/<day>_plan.json            (in_plan 标记)
输出：freeze["pool_snapshot"] = [ {sym, name, px, chg_pct, vol_lot, amt_wan, turn_pct,
                                    amt_ratio_prev, amt_ratio_rank, pattern, patterns,
                                    sig_date, bars_since_sig, l2, in_plan}, ... ]
```
⭐ **为什么必须是「池全量」而不是「队列交集」**：
只有覆盖「竞价时有数、**但盘中没进队列**」的标的，才有**对照组**。
否则样本 = 队列内那 15 只，**永远问不出「竞价有没有区分度」**。

**② `amt_ratio_prev` —— 补上「相对量」（选手竞价语义的核心）**
`amt_ratio_prev = 竞价成交额 / T−1 全天成交额`（T−1 日线由 `core.daily_src.load_daily` 取，已可得）。
理由：选手竞价看的是「**有没有量（抢筹）**」，而绝对额跨标的不可比（中际旭创 vs 新中港差 3 个数量级）。
派生 `amt_ratio_rank` = 该比值在池内的分位。

**③ `sentiment_pre` —— 把「② 早盘集合竞价」这一档落下来**
```
freeze["sentiment_pre"] = { ts, n_up_open, n_down_open, n_flat_open,
                            amt_total_wan, pool_median_chg, pool_chg_q25, pool_chg_q75,
                            by_pattern: {huigui: {n, median_chg}, zt_huicai: {...}} }
```
对应 SOP 里你早已裁定的 tiers：「① 早盘外盘 → **② 早盘集合竞价** → ③ 前日收盘」，
现存系统只实现了 ③（`scan_and_confirm.py:496-498` / `persona/sop_v0.toml:291` 自己写明）。

### 2.3 红线（不可动的三处）
1. `read_only: true` / **`orders_allowed: false`** —— `collect_daily_acceptance.py:227` 断言 `orders_allowed is False`，**改了验收立刻变红**。
2. **不 import、不写入任何决策链模块**（scan / ledger / decision_chain）。
3. 失败必须降级为「无文件 + stderr」，**不得让异常冒泡到计划任务层**（避免影响 09:30 的 scan）。

### 2.4 体积与验证
- 体积：1546 行 × ~90 B ≈ **150 KB/日**，且**只在 09:25 落一次**（不落每分钟）。
- 语法/回归：`python -X utf8 -m py_compile` + 现有 `tests/test_auction_monitor.py`（不得改动其断言）+ 全量测试。
- 冒烟（今晚可做，**不影响明早**）：`python -X utf8 scripts/auction_monitor.py --force` 走一遍，
  但**必须先把产物写到 `_scratch` 或接受它会覆盖今日 latest** —— 建议加 `--dry-run` 写 `outputs/auction/_dryrun/`。

## 5. P2（样本 ≥5 个交易日后）
**判别检验**（不是「调参」）：
- H0：`amt_ratio_prev` 高分组与低分组，**进队列率 / e4 触发率 / 触发后盈亏**无差异。
- 做法：按 `amt_ratio_prev` 分位分 3 档，比 `进队列率` 与 `触发后 T+0 收益`；同时按 `pattern` 分层（`huigui` / `zt_huicai` 分开）。
- **判定**：有区分度（且样本 n ≥ 30/组）→ 才考虑做成**排序权重**；**否决层最后做**（否决最伤样本）。
- 若 5 日后仍无区分度 → **结论就是「竞价对 e4 低吸无增量」**，也是一条有效结论，写进 SOP 结案。
