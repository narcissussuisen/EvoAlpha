## 1. 执行摘要

当前 EvoAlpha 不是由 AI Agent 驱动的交易团队，而是一个带调度、门禁、报告和角色名称的确定性规则引擎。核心证据如下：

1. 生产候选由 `plan_daily.py` 和 `scan_and_confirm.py` 的固定规则产生，团队研究 artifact、选手资料和 R6′ 候选表均没有生产消费者。
2. 两笔生产模拟买入的 `decision_id` 为空，`signal_requests` / `human_decisions` 为空；没有组合经理裁决、研究证据引用或交易员独立意见。
3. 所谓“五层交易团队”是脚本组件分层，不是拥有独立输入、记忆、观点、权限和绩效的智能体。
4. `trader_daily.py` 用固定 if 条件生成建议；`loop_engine.py` 只从预设模板取 pending 任务。它们不会摄取新资料、归因角色、提出新假设、自动验证和晋级策略。
5. R1′-R7′ 有大量严谨评审成果，但结论是：R1′ 仅获批为召回组件；R2′ 为条件化买点组件；R3′ 为条件化卖出机制；R4′/R5′ 多项驱动被拒；R6′ 机械复刻最佳约 0.92x，未达 3x；R7′ 四年约 0.89-1.01x。现有机械系统没有被证明具备正期望。
6. baseline-0 还存在回溯成交、收盘流水线必崩、计划与执行脱节、卖出覆盖不足等真实性缺陷。若不先修复，任何 Agent 收益和学习结论都不可信。

因此 Phase 1 不再增加“角色名”或“报告任务”，而是建立一个可证伪的闭环：

`资料原件 -> 证据分级 -> 规则假设 -> 09:14/09:39 Top 5 冻结 -> 选手标签导入 -> 误差归因 -> 实验 -> 20 标签日前向盲测 -> 自动晋级/回滚`。

## 3. baseline-0：当前生产真实行为

### 3.1 调度与数据流

`16:30 post-close -> r5p 情绪 -> r6p 候选表 -> 日线重建 -> 次日计划 -> 08:50 外盘刷新 -> 09:15 竞价只读 -> 09:30 扫描/风控 -> 15:10 close`。

关键事实：`premarket.py` 只刷新外盘并更新已有计划，不重算候选；`r6p_candidates_2026.csv` 仅被 preflight 检查新鲜度，未进入当日生产选股。

| 决策 | baseline-0 实现 | 审计判断 |
|---|---|---|

| 编号 | 缺陷 | 影响 | 施工前置验收 |

|---|---|---|---|
| R1′ 选股 | 26/41=63.4% 覆盖；仅放行为召回组件 | `detect_huigui_v5` 可作候选特征 | 不得单独产生交易信号或宣称选股 alpha |
| R2′ 买点 | realtime=True、max_pct=3 三引擎 29/48=60.4%，1136 日增量重放无差异 | B2/D/P 可作交易员特征 | max_pct=5、硬 day gate、shrink 过滤不放行 |

| W2 | 作为做多模式否决；开盘走弱规避有判别力 | 可作为否决特征候选 | 不得用10:00确认配开盘成交 |
| 打板/动量/回踩 | 修复止损引擎后多数年份为负 | 反例与失败模式 | 修复前正收益、+560%/+713%、+2097% 等全部作废 |

权威来源优先使用 `yaoban-system/docs/reviews/*`、`docs/loops/EVIDENCE_INVALIDATION.md`、修复后四年报告和独立复算产物。临时 probe、修复前回测和旧 `STAGE_STATUS` 数字不得作为晋级证据。

### 4.2 现有状态模型的问题

当前 `docs/loops/state.json` 的 `done/in_progress` 混合了五种不同含义：

1. 证据整理完成；
2. 实验运行完成；
3. 组件有条件放行；
4. 允许影子运行；
5. 允许生产交易。

Phase 1 必须改为显式状态机：

`discovered -> specified -> implemented -> backtest_passed -> oos_passed -> shadow_running -> promotion_ready -> production -> rolled_back/rejected`。

每个状态都必须有 gate 结果和不可变 artifact，不能因“文档完成”自动获得交易权。

### 5.2 证据等级

| 等级 | 定义 | 训练/验收用途 |
|---|---|---|
| E0 | 原始媒体、原始交割、账户截图、带平台发布时间的候选画面 | 最终仲裁源；构建强标签前仍需哈希和人工校对 |
| E1 | 带frame key、时间偏移和置信度的结构化OCR/ASR | 可追溯到原件；数值低置信度进入人工队列 |
| E2 | 原生键入的同期文本（含DOCX正文），时间可信 | 可构建规则和候选标签；图文关联必须保留原图 |
| E3 | 丢失置信度的逐字稿或标题/OCR摘要 | 只作候选线索；确认后升级 |
| E4 | 人工识读、人工日志 | 含推断，需回到原件复核 |
| E5 | 后期方法论总结、用户转述 | 用于提出假设，不作盲测真值 |
| E6 | 旧代码、旧参数、模型推断 | 仅作历史线索，不得证明选手行为 |

冲突裁决遵守用户确认的语义顺序：实际行为 > 同期原话 > 后期总结 > 旧代码；技术来源等级只衡量可追溯性，不能让高质量OCR标题覆盖低层级但明确的实际交割。同级冲突不静默覆盖，保留多版本并标记 `disputed`。数值字段只接受可回溯的E0-E2来源。

### 5.3 新资料目录契约

`选手学习资料/文字资料/YYYY-MM-DD_HHMM_主题/record.md`：

`record.md` 必填字段：

- `source_id`、原始聊天/发布时间、整理时间、资料类型；
- 来源 URL/文件；时区；公开时点可信度；
- 原文与用户理解分栏；
- 候选代码/名称（如有），无序/有序声明；
- 操作代码、方向、时间、价格、数量（只在原件明确时填写）；
- 账户总资产、现金、仓位、持仓（只在原件明确时填写）；
- 图片相对路径。

图片保存在 `images/`，Markdown 使用相对路径引用；禁止 base64。摄取器保存原文件 SHA-256、OCR/视觉提取结果、人工校对状态；派生产物不覆盖原件。

### 5.4 标签对象

每日标签至少分四类：

- `idea_set`：公开候选，无序集合；
- `execution`：实际买卖，来自交割/持仓变化；
- `portfolio_snapshot`：资产、现金、仓位和持仓；
- `method_claim`：规则原话与失效条件。

缺失不填零。无法确认选手空仓时，不得把“无资料”解释为“无候选”。

## 6. Phase 1 真实 Agent 团队

角色数量服务于职责，不为展示而设。第一期保留六个角色：

| 角色 | 专属输入 | 输出/权限 | 绩效与成长 |
|---|---|---|---|
| 证据研究员 | 原始资料、OCR、交割、时间戳 | 标准证据、冲突/缺口；无交易权 | 标签准确率、冲突发现、校对返工率 |
| 策略研究员 | 证据、历史行情、失败实验 | 可执行规则假设、特征、反例、实验计划；可在隔离区改码 | OOS增量、泄漏缺陷率、假设通过率 |
| 选股研究员 | 当时可用市场数据、批准规则 | 09:14/09:39候选与解释；不能下单 | Top5 precision/recall、漏选/误选归因 |
| 交易员 | 已批准候选、分钟行情、成交约束 | 影子组合买点/卖点/可成交性意见 | 滑点、机会成本、执行一致性 |
| 组合经理 | 各角色签名 artifact、账户风险 | 最终影子订单裁决、仓位；必须写 decision_id | 风险调整收益、裁决增量、错误归因 |
| 风控审计员 | 全部 artifact、数据质量、敞口、回撤 | 不可绕过 veto、暂停、回滚；不能创造买入理由 | 漏拦截、误拦截、恢复时效、审计完整性 |

复盘不是额外“写报告角色”，而是每日 attribution job：把每个决策结果归因给提出者、裁决者和阻断者，更新能力分。角色成长只能经版本化变更实现：权重、记忆条目、SOP、工具权限、风险预算都要有前后版本、原因和回滚点。

### 6.1 决策契约

每个影子订单必须引用：

- `candidate_snapshot_id`；
- 证据/规则版本；
- 六角色 artifact 哈希；
- 组合经理 `decision_id`；
- 风控 gate 结果；
- signal_ts、decision_ts、fill_ts、recorded_at；
- 成交模型版本。

缺一项则 fail-closed，不允许影子成交。

## 7. Phase 1 数据与运行闭环

### 7.1 双 Top 5 冻结

每日产生两份 baseline 和 challenger 快照：

| 快照 | 截止信息 | 用途 |
|---|---|---|
| 09:14 Top 5 | T-1数据、盘前研究、09:14前可用信息 | 开盘候选；09:30后交易员可自主找买点 |
| 09:39 Top 5 | 集合竞价和09:30-09:39早盘数据 | 在选手约09:40公开前冻结；妖板复现主指标 |

快照必须原子写入、内容寻址、带输入manifest/hash，并追加到append-only索引。标签到达后只能新增evaluation，不能重写预测。标签到达时间以摄取器生成的append-only receipt为准，时区为Asia/Shanghai；交易日当日24:00前到达且自动校对通过的标签计入该版本20日主指标，24:00后到达或后续修订只进入审计与辅助分析，不改变主指标。

### 7.2 指标

选手候选为无序 Top 5，主指标：

- intersection count；
- Precision@5；
- Recall@5；
- exact-set match；
- 误选清单与漏选清单；
- 09:14 -> 09:39 新增/删除及信息贡献；
- baseline-0 与 challenger 的成对差异。

若某日选手有效候选不是5只，按实际集合分母计算并标记异常原因。无标签日不进入累计指标。

### 7.3 影子组合

- 初始资金：100,000元；
- 独立 ledger，不写当前生产账本；
- 使用当前保守费用、滑点、T+1、涨跌停、一字板、成交量参与率约束；
- 09:14候选可从09:30开始执行，不等待选手09:40标签；
- 选手标签只用于盘后评价，严禁同日反向影响已冻结决策；
- 同时维护baseline-0、各活跃challenger版本、选手归一化净值多条曲线；
- 影子成交分两类口径维护：Phase 1C上线前对已冻结1B快照用当日原始行情与当时版本做的确定性重放标记 `replayed`；1C上线后实时产生的成交标记 `forward_shadow`；两条曲线分别报告，禁止合并冒充前向影子绩效；
- 选手逐日净值只在有资产/仓位证据时记录；当前28个可解析净值点须先剔除2个陈旧截图伪点并处理3个同日多值，7月44天断裂不插值冒充真实数据。

## 8. 学习、实验与自动晋级

### 8.1 每日学习循环

1. 摄取当天新增原件，验证 hash、时间和来源；
2. 09:14 冻结 baseline/challenger Top 5；
3. 09:39 再冻结一组 Top 5；
4. 标签到达后解析 idea_set；Agent 自动校对通过后计分，只有低置信、来源冲突或无法回溯原件的项目进入人工抽检队列；
5. 生成命中、漏选、误选差异；
6. 证据研究员找对应原话/行为；策略研究员提出可证伪假设；
7. 风控审计员检查未来数据和选择偏差；
8. 实验进入隔离队列，不直接改生产；
9. 盘后完成影子成交、角色归因和能力分更新；
10. 达到门禁的版本进入 promotion_ready。

### 8.2 实验最小契约

每个实验必须包含：假设、资料来源、反例、训练截止日、OOS窗口、特征可用时点、baseline版本、代码hash、数据hash、预注册指标、成本模型、结果和失败原因。禁止看到 OOS 结果后原地修改同一实验；修改必须生成新 experiment_id。

challenger v0 是 baseline-0 的逐字克隆，只验证冻结、评分和对照管线的零差异，不申请晋级。Agent 的首次学习改动产生 v1，后续每次规则、参数、特征或角色权重变化生成新的不可变 vN。每个 vN 必须在其首个计分日 09:14 前完成注册，记录 parent_version、code/config/data hash 和预注册假设；禁止看到当日标签后补注册。各版本从注册后的第一个有效标签交易日起独立累计20日，窗口允许重叠、每日并列冻结。默认同时活跃的非v0 challenger上限为4个；超限时只能在当日09:14前按预注册淘汰规则归档，不能看标签后择优保留。

### 8.3 自动晋级门禁

每个challenger版本连续累计至少20个自身有效标签交易日后才可申请晋级。总观察时钟从Phase 1B冻结机制上线后的第一个有效标签交易日起启动；后出生版本不得继承出生前样本。Phase 1C/1D的施工与上线不重置总观察时钟，也不要求重新等待20日；影子组合与晋级门禁就绪后直接在同一观察期的既有样本上做终审。必须同时满足：

1. 在预注册的20个同日标签样本上，challenger 的平均intersection count高于baseline-0，且逐日胜出天数严格多于落后天数；平局不自动晋级；
2. 无未来数据、标签泄漏和回溯成交；
3. 所有影子订单通过不可交易、T+1、费用、滑点和风控门禁；
4. 模拟风险不失控：不得触发15%终止回撤；若最大回撤或成本后收益显著劣于 baseline，拒绝；
5. 所有决策和版本 artifact 完整可重放；
6. 风控审计员签名通过。

第一期不把分市场环境和规则可解释性设为硬统计门槛，但必须报告。晋级后先进入 canary 影子权重，不能直接覆盖旧版本；异常自动回滚到上一生产策略版本。

## 9. 施工分解与验收

### Phase 0：真实性与基线冻结

Phase 0决定施工验收顺序，但不要求资源完全串行。Phase 1A中不读取、不写入生产账本和交易代码的资料工作（manifest、SHA-256、去重、ASR/OCR、coverage report）可与P0.2-P0.4及P0.3连续5日观察并行；1A的正式标签发布仍必须通过自身验收。

| 任务 | 交付 | 验收 |
|---|---|---|
| P0.1 baseline manifest | 当前代码、参数、任务、数据和账本哈希 | 同一输入可重放同一 Top 5 |
| P0.2 成交时序修复 | signal freshness 与单调时间契约 | 强制 signal_ts <= decision_ts <= recorded_at；成交只能使用decision之后的下一根bar；decision时旧信号超过120秒一律拒单 |
| P0.3 close 修复 | 收盘链、净值、熔断、日报 | 连续5个交易日 exit0；失败 fail-closed |
| P0.4 决策 provenance | snapshot/decision/risk/fill 全引用 | 任何空 decision_id 拒绝写影子账本 |
| P0.5 证据失效表 | 作废回测和权威评审清单 | 旧正收益不得被晋级器消费 |

### Phase 1A：资料与标签层

- 建立 source manifest、SHA-256、证据等级和去重；
- 转换旧 DOCX，但保留原件；
- 建立 Markdown+images 模板；
- 从82个原始视频、4,100帧结构化OCR、88份OCR MD和现有日志构建候选/交割/净值coverage report；
- 优先补齐ASR、10个未处理视频和3张未OCR图片；
- 只有能够回到原件、时点可信且通过Agent自动校对的候选进入正式标签集；OCR低于阈值、跨源冲突、日期/代码无法唯一确定时升级人工抽检。历史7组完整标签只作种子集，20日晋级观察主要依赖后续每日前向标签。
- 自动校对必须同时执行OCR/ASR置信度阈值、原件frame回溯、股票代码/名称规范化、发布时间边界和至少一个独立来源交叉验证；无法交叉验证时进入review_queue，不允许模型凭语义猜测。目标用户人工投入不超过每日5分钟。

验收：随机抽取20条标签可追溯到原件；冲突和缺失不静默覆盖；未来时点字段完整；自动校对结果含置信度和逐项检查，只有review_queue需要人工，按连续10个资料日统计用户人工处理时间中位数不超过5分钟/日；并行施工约束可审计——1A工作期间对生产账本、ledger与生产交易代码的写入记录为零，发现一次违规即1A当批产物全部作废。

### Phase 1B：双榜单与对照

- baseline-0 与 challenger 各生成09:14/09:39 Top5；
- append-only 冻结与迟到标签评估；
- Top5 对照第一屏。

验收：断网/任务重跑不能重写已冻结快照；在标签文件投放前后预测hash不变；v0与baseline-0必须逐日完全一致；每个vN均在首个计分日前注册并拥有独立20日计数器，看到当日标签后补建的版本一律拒绝入库；标签到达receipt为append-only、时区Asia/Shanghai，24:00后到达或修订的标签只进入审计通道，机械检查须能验证其未计入任何版本的20日主指标；同时活跃的非v0 challenger超过4个时，必须能出示09:14前的预注册淘汰记录，无法出示则当日全部超限版本只作废不评分。Phase 1B上线后的首个有效标签日启动总观察时钟。

### Phase 1C：Agent 团队与影子组合

- 六角色独立 artifact/schema；
- 组合经理裁决与风控 veto；
- 100,000元独立影子账本；
- 每笔订单完整 provenance；
- 角色能力账本。

验收：注入角色冲突时能看到独立意见；组合经理可裁决，风控veto无法绕过；无artifact不成交。Phase 1C上线前已经冻结的1B日期可用当日原始行情和当时版本做确定性成交重放，但必须标记replayed；只有1C上线后实时产生的成交标记forward_shadow，两类风险收益分别报告，不能合并冒充前向影子记录。

### Phase 1D：实验、晋级与回滚

- 假设/实验 registry；
- 隔离实现与无泄漏检查；
- 20标签日成对比较；
- promotion gate、canary、版本 registry 和 rollback。

验收：故意引入未来特征必须被拒；失败版本不能改变生产；通过版本可一键重放并自动回滚。
